## ⚠️ 事故发现：crewboard 被 pm2 每 10 分钟强制重启（本次会话最重要产出）
- auth-watchdog 日志：部署后 21 次自检 0 PASS，全部 "FAIL: fetch failed"，
  并按 15min 冷却反复 pm2 restart crewboard + 给 kris.wang@ 发告警邮件（整晚每 10~20 分钟一封）。
- 根因：**pm2 内存中 crewboard 进程配置带 `cron_restart: "*/10 * * * *"`**（疑为早前事故
  救火时以 `pm2 start ... --cron-restart` 类方式启动后残留的漂移配置；仓库 ecosystem.config.js
  中 crewboard 从无 cron_restart）。现象链：pm2 每 :X0:00 强杀重启 crewboard →
  0.2 秒后 watchdog 自检撞上重启窗口连接失败 → 误判故障再重启 + 误发告警邮件 → 循环。
  这也解释了用户当晚体验异常、重复报障。
- 佐证：crewboard 应用日志每个整十分钟都有 "running at" 启动行；watchdog 冷却跳过重启的
  时刻（07:20/07:40 local）crewboard 依然被重启。
- 修复（07:58 local / 23:58 UTC）：
  ```bash
  pm2 delete crewboard
  pm2 start ecosystem.config.js --only crewboard   # 干净配置，无 cron_restart
  pm2 save
  ```
  ⚠️ `pm2 restart`/`startOrReload` 都不会清除内存中已有的 cron_restart（合并而非替换），
  必须 delete 后重新 start。
- 验证：手动跑 `node scripts/auth-watchdog.js` → OK（login + session lookup healthy）；
  00:00 UTC 整点 tick：crewboard pid 不变、restarts=0、watchdog 首次计划内 PASS、
  https 站点 200。告警邮件轰炸自此停止。
