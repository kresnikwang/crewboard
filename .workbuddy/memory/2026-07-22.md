# 2026-07-22 邮件功能完善 + 部署

## 变更内容（commit 见 git log "feat(email)"）

### 修复：token/session 过期比较 bug（安全）
- `expires_at` 以 ISO-8601（`toISOString()`）存储，但 SQL 里用 `datetime(?)`
  （'YYYY-MM-DD HH:MM:SS' 格式）做字符串比较。因 `'T' > ' '`，同日过期的
  token 会被误判为有效 → **重置密码 token 的 30 分钟有效期实际失效**。
- 已修复 4 处（全部改为 ISO 字符串直接比较）：
  - `routes/auth.js` GET/POST `/reset-password`（2 处）
  - `utils/authz.js` `authMiddleware` session 校验
  - `utils/authz.js` `cleanupExpiredAuth` 清理任务

### 新增：登录用户接受邀请
- 已有账号（无企业）的用户点邀请邮件链接时，之前无法加入企业
  （邀请只在注册时按邮箱匹配消费）。
- 新增 `POST /api/auth/invitations/accept`（需登录，校验邀请 token +
  邮箱必须与当前账号一致，防冒领）。
- 前端两处自动接受：
  - `handleHashRoute()`：已登录状态打开 `#register?invite=...` → 直接接受并进应用
  - `initLoginHandler()`：登录后若带着邀请 hash 且无企业 → 自动接受
- 邀请接口响应新增 `invite_link` 字段；邮件发送失败时前端报错 toast 并
  复制邀请链接到剪贴板（兜底手动转发）。

## ⚠️ 服务器 git push 方式（重要）
- 服务器 SSH deploy key 是 **只读**（`git push` 报 "key marked as read only"）。
- 正确做法：服务器 `/root/.git-credentials` 存有 GitHub HTTPS 凭据
  （`credential.helper=store`）。push 前临时把 origin 切成
  `https://github.com/kresnikwang/crewboard.git`，push 后再切回
  `git@github.com:kresnikwang/crewboard.git`。
- 本地沙箱的 origin token（gho_…）已失效，无法从本地直接 push；
  需 `git format-patch` → scp 到服务器 → `git am` → 在服务器上 push。
